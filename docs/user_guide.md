# SymDCT user guide

SymDCT computes diffusion coefficients in crystalline solids from a structure
model and user-supplied energetics. The pipeline has four stages:

- construct a jump network from a POSCAR and geometric cutoffs
- build the symbolic transition-rate matrix and reduce it for each direction
- solve for the symbolic diffusion coefficient
- evaluate the expressions numerically and generate Arrhenius plots

A single script, `main.py`, runs the whole pipeline in one command. Each stage
also has its own command-line interface.

## Pipeline overview

| Stage | Role | Main inputs | Main outputs |
|---|---|---|---|
| 1. `src.jump_network_builder` | Build the jump network geometry | input YAML, POSCAR, optional `cutoffs.yaml` | `jump_structure.node_link.json`, `jump_sites.poscar`, `energetics_template.yaml` |
| 2. `src.matrix_builder` | Build full and axis-reduced symbolic transition matrices | Stage-1 graph artifacts, input YAML axes/settings | `tp_matrix_axis_<h>_<k>_<l>.m`, `tc_axis_payload_<h>_<k>_<l>.pickle` |
| 3. `src.transport_coefficient_solver` | Solve symbolic diffusion coefficients | Stage-2 payload pickles | `dc_symbolic_<h>_<k>_<l>.txt`, `dc_symbolic_<h>_<k>_<l>.m` |
| 4. `src.transport_coefficient_evaluator` | Substitute energetics and plot Arrhenius curves | Stage-3 symbolic expression, `energetics.yaml`, Stage-1 template | `arrhenius_plot_<example>_<h>_<k>_<l>_freq<model>.png` |

## Why use the full pipeline vs individual stages

- Use `main.py` when you want the fastest end-to-end route from structure to
  symbolic and numeric diffusion results.
- Use the individual stage CLIs when you want to inspect intermediate
  artifacts, debug one step, or rerun only part of the workflow.

## Canonical input/output layout

Each example should follow this structure:

```text
examples/<example>/
├── input/
│   ├── <example>.yaml
│   ├── POSCAR
│   ├── cutoffs.yaml               # optional but strongly recommended
│   └── energetics.yaml            # required for Stage 4
└── output/                        # created automatically
```

Key conventions:

- `<example>.yaml` is the main stage-driving config
- `fname` inside that YAML may be relative to the YAML file
- `cutoffs.yaml` defines pair-specific geometric cutoffs for Stage 1
- `energetics_template.yaml` is generated by Stage 1 into `output/`
- `energetics.yaml` is hand-authored input kept in `input/`, not `output/`

## Quick start

All commands below are run from the root of the repository.

### Run the full 4-stage pipeline

```bash
uv run python main.py examples/hcp_vac/input/hcp_vac.yaml
```

This route:

1. loads the YAML and POSCAR
2. auto-discovers `input/cutoffs.yaml` when present
3. runs Stages 1-3 in memory
4. runs Stage 4 if `input/energetics.yaml` exists
5. writes artifacts into `examples/<name>/output/` (not tracked by git; reference
   results of the examples are kept in `examples/<name>/assets/`)

If `input/energetics.yaml` is missing, `main.py` logs a warning and skips
Stage 4 instead of failing.

### Run stages separately

Use the per-stage READMEs for exact CLI details:

- Stage 1: `src/jump_network_builder/README.md`
- Stage 2: `src/matrix_builder/README.md`
- Stage 3: `src/transport_coefficient_solver/README.md`
- Stage 4: `src/transport_coefficient_evaluator/README.md`

## Pipeline artifacts

After a successful end-to-end run, `output/` contains some or all of:

- `jump_structure.node_link.json`
- `jump_structure.adjlist`
- `jump_sites.poscar`
- `energetics_template.yaml`
- `tp_matrix_axis_<h>_<k>_<l>.m`
- `tc_axis_meta_<h>_<k>_<l>.m`
- `tc_axis_payload_<h>_<k>_<l>.pickle`
- `dc_symbolic_<h>_<k>_<l>.txt`
- `dc_symbolic_<h>_<k>_<l>.m`
- `arrhenius_plot_<example>_<h>_<k>_<l>_freq<model>.png`
